# 3.2 邀请解锁：规则、归因与验收

用户确认日期：2026-09-14；实现验收跨至 2026-09-15。当前开发版本为 **3.2.0 / build 6**。本功能代码和本地验证不代表生产活动已经开放。

## 已确认的规则

- 免账号登录，每台设备在当前版本系列先免费成功录音 **5 次**。
- 成功生成可用 ALAC 录音算一次，不以打开应用或点击开始计次；取消倒计时、采集/封口失败不扣次。重新导出同一录音不重复扣次。
- 邀请 **2 台有效新设备**后，为邀请设备授予当前主次版本系列（例如 3.2）的无限次数免费录音权益，无到期时间。同系列修复版继承，其他系列和其他设备不自动继承。
- 免费权益与版本准入分别验证。每次录音仍需联网；最高档强制升级照常生效。这里的无限指录音次数，不承诺无限时长或永久离线。
- 第五次录音及以后已经生成的文件始终可以停止、保存和再次导出，不能把文件作为解锁条件扣押。

## 实际用户流程

1. 邀请人在应用中复制个人邀请链接，分享给好友。
2. 好友打开邀请页面，领取七天有效的下载/激活凭证。
3. 邀请服务直接发送已核验 SHA-256 的固定 ZIP 安装包，记录完整发送。浏览器中断、只请求 HEAD、字节数不完整、摘要不符，不算下载完成。
4. 好友安装后回到页面，点击“打开录音机并激活邀请”。系统通过 `lossless-recorder://activate?ticket=...` 交给应用；系统无法打开时，可在应用中粘贴激活码。无需登录。
5. 服务核对完整发送记录、凭证有效性和设备是否新激活；关联成功后，好友完成首次成功录音，邀请人的有效人数加一。
6. 两位好友均满足条件后，邀请人刷新进度或再次录音时获取签名权益，显示本系列已无限免费。

**归因需要安装后的激活动作。**不能仅凭通用 ZIP 下载就把浏览器里的邀请标识自动交给新安装应用；当前采用用户明确点击的应用链接，不读取浏览器历史，不用 IP 猜设备，也不修改已公证的应用包。现阶段未实现零点击的延迟深链归因。

## 新设备与防重复

应用在钥匙串保存不经 iCloud 同步的 Ed25519 设备私钥；把规范化的 Mac 平台 UUID 加本应用命名空间做本地 SHA-256，只上传摘要。服务再用独立秘密值做 HMAC 后存储，与公钥摘要分别建立唯一约束。普通重装不会重置身份或试用次数；原始 UUID、序列号、音频和文件路径不上传。

每个请求用本机私钥签名并携带新 nonce、时间、构建号和系列，服务验证并持久化防重放记录。响应由版本服务私钥签名，客户端核对本次 nonce、设备公钥、系列、时效与操作标识。没有登录也不能靠篡改本地邀请人数解锁。

每个下载凭证仅关联一台设备；已激活设备、自邀、重复凭证和重复完成请求不再次发奖励。一台受邀设备只贡献一次新设备资格，不能跨邀请人或跨系列反复贡献。首次成功录音之前才可关联邀请；已经使用过的老设备不能后来补填邀请当作新用户。

上述机制能阻止正常客户端重复领取，**不是不可伪造的物理设备证明**。自行修改客户端、伪造硬件摘要、批量虚拟机等仍可能绕过“新设备”声明；没有账号或平台可信设备证明，不能把该指标宣传为经实名核实的新用户数。

## 额度预约和故障恢复

开始准备设备之前，客户端创建并持久化操作标识，再请求服务预约一次额度；倒计时结束时，以同一标识再次确认版本和预约。5 次额度包含已成功使用和当前预约，防止多进程同时预约超额；已解锁设备不受次数上限，但仍走同一在线协议。

成功封口后先在本机原子记录完成事件，再异步结算，不让保存面板等待网络。服务按操作标识幂等完成、取消；已完成不能退款，取消墓碑阻止旧预约请求晚到后重新占额。网络失败下次刷新继续重试，重复导出没有结算动作。

开始实际录制前另写入 `recording` 状态。崩溃前尚未开始的预约可取消恢复；已进入录制但没有可靠完成/取消记录的异常状态不会自动退款或冒充好友首次使用，暂留预约并提示核对。完成事件写盘失败时保留内存结算意图，新的录音须先可靠写入；已有文件依然可保存。生产需提供这类异常预约的人工核对路径，不得直接清空设备数据库“恢复次数”。

命令行 `--verify-capture` 使用相同版本与额度门，每次成功验收录音也消耗试用次数。没有离线绕过开关。已经初始化邀请服务的数据库在缺少邀请配置时拒绝启动，不能静默恢复旧版不计次流程。

## 服务与数据

新增签名接口：`POST /v1/referral`，动作包括 `status`、`claim`、`begin`、`complete`、`cancel`。网页入口 `/r/<referralCode>`，凭证生成 `/r/<referralCode>/ticket`，完整文件发送 `/r/download?ticket=...`。

持久化保存设备摘要、系列权益、下载凭证、完整发送状态、首次成功使用、邀请关系和幂等操作。普通入口请求数、完整发送数、新设备激活数、有效邀请数与解锁数分别统计，不能相加当成用户总量。详见 [服务运维](server-operations.md)与[隐私说明](privacy.md)。

## 正式开放前的必要验收

- 在真实 HTTPS 服务部署策略、邀请服务和持久数据库，绑定正式公钥及设备去重秘密值；开启活动后，服务对低于 build 6 的旧版始终返回签名强制升级策略，不受轻提醒档位影响，防止旧 build 5 绕过额度。
- 用最终签名、公证 ZIP 配置服务的文件、SHA-256、build 和 series，核对生成链接、下载、应用链接、钥匙串权限与真实包一致。不能把测试假 ZIP 外发。
- 在三台真实 Mac 上由一台邀请两台，确认完整下载、主动激活、首次录音、0→1→2、五次前后、同系列更新继承、最高档停用、断网恢复和重复安装去重。
- 校验在支持浏览器中安装后点击应用链接可达；跨设备复制激活码和旧设备补领被拒，凭证过期提示清楚。
- 配置反向代理请求限制、下载带宽/并发限制、存储告警、证书续期、密钥与数据库备份恢复，以及不含凭证/设备摘要的访问日志。
- 上线明确的隐私/许可页面、数据处理及异常权益联系入口；不能继续宣传无设备统计或完全离线。

## 实现依据

应用链接遵循 [Apple：自定义 URL scheme](https://developer.apple.com/documentation/Xcode/defining-a-custom-url-scheme-for-your-app) 和 [SwiftUI onOpenURL](https://developer.apple.com/documentation/SwiftUI/View/onOpenURL(perform:))。设备私钥采用不跨设备同步的钥匙串保存方式，参见 [Apple：设备限定的钥匙串可访问性](https://developer.apple.com/documentation/security/ksecattraccessibleafterfirstunlockthisdeviceonly)；本机编译不替代真实签名包下的钥匙串/更新连续性验收。
