# 分档升级与强制在线版本验证（3.1.0 / build 5）

本次实现基于原有录音流程，复用浩宇的 Sparkle 2.9.6 接入方式。产品独立使用更新清单、版本策略和签名密钥，不复用浩宇的产品身份或私钥。源码接入不代表线上服务已经启用。

## 五档策略

| level（档位） | 行为 |
| --- | --- |
| 0 | 不显示更新提示，仍执行在线版本验证 |
| 1 | 轻量提示，可关闭 |
| 2 | 更明显提示，可关闭，允许继续录音 |
| 3 | 低于 minimumBuild（最低允许构建号）的版本在 effectiveAt（生效时间）之后不能开始新录音 |
| 4 | 低于 minimumBuild 的版本立即不能开始新录音，不等待 effectiveAt |

是否恢复使用依据实际运行的构建号重新在线验证，点击下载本身不会解锁。最高档停止新录音入口；已在录的内容可以停止、保存，已有文件不删除。登录、付费和增值功能尚未实现。

## 必须联网，错误时拒绝新录音

每次开始或再次录制，准备设备之前和倒计时结束时分别请求新策略；命令行 `--verify-capture` 也经过相同验证。启动和回到前台时另做提示刷新。关闭 Sparkle 自动检查仅关闭更新提醒，不关闭准入验证。

策略由服务端 Ed25519（数字签名算法）私钥签名，客户端只持有公钥。签名内容绑定本次 nonce（随机挑战值）、构建号、产品、递增策略序号、签发时间和最长 60 秒有效期。拒绝错误签名、错 nonce、错误产品、过期和回退策略；不缓存可供下次录音的许可。断网、服务故障、缺配置或校验失败，均不能新建录音。当前录音不会被后台策略刷新强制打断。

本地仅保存见过的最高策略序号，防止旧策略回退。系统时钟需正常。客户端无法保证抵抗用户修改二进制；历史 MIT 版本及已流出的旧副本不能追溯撤销。本仓库正常打包路径没有离线开关，缺四项正式配置就拒绝生成应用。

## 更新安装与文件保护

Sparkle 自动检查默认关闭，不自动下载或安装；菜单提供手动检查。更新签名清单和安装包均需校验。准备、倒计时、录音、导出及有未保存文件时禁止安装；忙碌时保留安装回调，保存后由用户继续安装。后台检查/下载不等于安装，不锁住正在使用的录音功能。

无待安装更新时仍保留 3.0 的普通退出语义：录制中关闭会放弃尚未导出的片段，请先停止并导出。

## 四项打包配置

- `LOSSLESS_RECORDER_UPDATE_FEED_URL`：本产品正式 HTTPS appcast（更新清单）。
- `LOSSLESS_RECORDER_UPDATE_PUBLIC_KEY`：Sparkle Ed25519 公钥，Base64 编码。
- `LOSSLESS_RECORDER_POLICY_URL`：正式 HTTPS `/v1/policy` 地址。
- `LOSSLESS_RECORDER_POLICY_PUBLIC_KEY`：版本准入 Ed25519 公钥，Base64 编码。

两套私钥分别管理，不进仓库和应用。模板没有默认生产地址、公钥或后门。完整配置只证明格式有效，不证明地址已上线、密钥匹配或新包可下载。

`build-app.sh` 编译并生成隔离候选包；`prepare-release.sh` 强制双架构、Developer ID 签名、公证、装订票据和发布审计。应用内包含自有许可、隐私说明和 Sparkle 许可。详见[服务端操作](server-operations.md)与[发布准备检查](release-readiness-2026-09-15.md)。

## 下载统计

服务端 `/download` 记录按 UTC 日期、渠道汇总的下载入口 GET 次数，再跳转到固定版本资产。管理接口另列 GitHub Release 资产下载计数。两者不相加，也不等于下载完成数、安装数或独立用户数。没有账号、设备 ID 或音频上传；详见[隐私说明](privacy.md)。

## 验收边界

本机覆盖签名、nonce、时效、回退、分档、联网失败、倒计时再验证、保存保护、更新安装保护和服务端统计。正式发布前仍须部署真实 HTTPS 服务及签名清单，以可下载的新包验证一次真实旧版到新版安装，并完成断网拒绝/恢复及正在录音时停用保护。新包需要单独公证，不能沿用旧包验收结论。
